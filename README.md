# Практическая работа: Асинхронный сервис аналитики прогноза погоды

В этом проекте вы создадите модульный бэкенд-сервис на **FastAPI**, который узнаёт текущую погоду через внешний **OpenWeatherMap API**, сохраняет историю запросов в локальную асинхронную базу данных **SQLite** и рассчитывает аналитику по собранным данным.

## Цель задания

* Научиться строить проект с правильной архитектурой (разделение на модули: конфигурация, БД, внешний API, аналитика, маршруты).
* Освоить безопасное хранение секретных ключей через файл `.env`.
* Реализовать асинхронные операции с базой данных (**Create, Read, Delete**).
* Написать модуль аналитики данных на Python.

## Подготовка и запуск

### 1. Установка библиотек

Убедитесь, что в файле `requirements.txt` указаны все зависимости:

```text
fastapi
uvicorn
aiosqlite
requests
python-dotenv
```

Откройте терминал в папке с проектом и установите их одной командой:

```bash
pip install -r requirements.txt
```

### 2. Настройка файла `.env`

В корне проекта создайте файл с именем `.env` (без названия перед точкой) и добавьте в него следующие строки:

```env
OPENWEATHER_API_KEY=ваш_реальный_ключ_от_openweather
DB_NAME=weather.db
```

> ** Важно о безопасности:** В реальных проектах API-ключи, пароли от баз данных и токены **никогда** не пишут прямо в Python-коде. Их выносят в `.env`, а сам файл `.env` добавляют в `.gitignore`, чтобы секреты не попали в публичный репозиторий на GitHub.

### 3. Запуск сервера

Выполните в терминале команду:

```bash
uvicorn main:app --reload
```

Если всё настроено верно, сервер запустится по адресу `http://127.0.0.1:8000`, а в папке с проектом автоматически создастся файл базы данных `weather.db`.

## Ваше задание: Доделать программу

Модули `config.py`, `weather_api.py` и `main.py` уже готовы. Ваша задача — реализовать недостающие функции в файлах **`database.py`** и **`analytics.py`** (все места помечены комментарием `TODO`).

### Часть 1. База данных (`database.py`)

1. **`save_weather_to_db(city, temp, description, wind)`**
   * Откройте соединение с `DB_NAME` через `async with aiosqlite.connect(DB_NAME) as db:`.
   * Выполните SQL-запрос `INSERT INTO weather_history (city, temperature, description, wind_speed) VALUES (?, ?, ?, ?)`.
   * Сохраните изменения командой `await db.commit()`.

2. **`get_weather_history()`**
   * Выполните запрос:
     
     ```sql
     SELECT id, city, temperature, description, wind_speed, created_at
     FROM weather_history
     ORDER BY id DESC
     ```
   
   * Получите все строки через `await cursor.fetchall()`.
   * Верните список словарей вида:
     
     ```python
     {
         "id": row[0],
         "city": row[1],
         "temperature": row[2],
         "description": row[3],
         "wind_speed": row[4],
         "created_at": row[5]
     }
     ```

3. **`delete_city_history(city)`**
   * Выполните запрос:
     
     ```sql
     DELETE FROM weather_history WHERE LOWER(city) = LOWER(?)
     ```
   
   * Сохраните изменения (`await db.commit()`) и верните количество удалённых строк (`cursor.rowcount`).

### Часть 2. Аналитика данных (`analytics.py`)

1. **`calculate_general_stats(records)`**
   * Если список `records` пуст — верните `{"message": "Нет данных для анализа"}`.
   * Вычислите среднюю температуру по всем записям (округлите до 1 знака с помощью `round()`).
   * Найдите самую тёплую запись, самую холодную запись и запись с самым сильным ветром (используйте `max()` / `min()` с `key=lambda r: ...`).
   * Верните словарь с ключами: `total_records`, `avg_temperature`, `hottest`, `coldest`, `windiest`.

2. **`get_city_summary(records, city)`**
   * Отфильтруйте `records`, оставив только записи для нужного города (без учёта регистра).
   * Если записей нет — верните словарь с сообщением об отсутствии данных.
   * Посчитайте количество проверок, среднюю, минимальную и максимальную температуру для этого города.
   * Сформируйте совет по одежде (`advice`) в зависимости от средней температуры:
     * ниже `0°C` — `"Одевайтесь тепло, на улице мороз!"`
     * от `0°C` до `15°C` — `"Прохладно, лучше взять куртку."`
     * выше `15°C` — `"Тепло, можно идти налегке."`
   * Верните итоговый словарь.

## Как проверить свою работу

Откройте в браузере интерактивную документацию Swagger UI: **[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)**

1. **Наполните базу данными:** выполните `POST /weather/{city}` для 3–4 разных городов (например, `Москва`, `Иркутск`, `Сочи`, `Владивосток`).
2. **Проверьте историю:** вызовите `GET /history` и убедитесь, что все запросы сохранились в обратном порядке (новые сверху).
3. **Проверьте общую аналитику:** вызовите `GET /analytics` — должны отобразиться средняя температура, самый тёплый, самый холодный и самый ветреный город.
4. **Проверьте аналитику по городу:** вызовите `GET /analytics/{city}` для одного из сохранённых городов и проверьте статистику вместе с советом по одежде.
5. **Проверьте удаление:** вызовите `DELETE /history/{city}`, а затем снова откройте `GET /history` и убедитесь, что записи удалены.

> **Подсказка:** OpenWeatherMap возвращает названия городов на русском языке (параметр `lang=ru`). Если вы запрашивали `Moscow`, в базе сохранится `Москва` — используйте это же название для аналитики по городу и удаления.
